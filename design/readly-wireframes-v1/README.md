# Readly 와이어프레임 v1

데스크톱 1440px와 모바일 390px 기준, 흑백으로 정보 배치와 탐색 흐름을 검토하는 시안입니다.
실제 앱 코드는 변경하지 않았습니다. 도서 표지는 의도적인 자리 표시자이며 기록·댓글·집계 수치는 예시입니다.

## Figma로 가져오기

1. `screens` 폴더의 `.svg` 파일을 선택합니다.
2. Figma Design 파일을 열고 캔버스의 빈 곳에 드래그합니다.
3. 파일 이름 순서대로 배치해 검토합니다. `01b`, `03b`, `04b`, `06b`, `07b`, `08b`~`08e`는 대체 상태입니다.

`mobile-`로 시작하는 파일은 모바일 화면입니다. 모바일 전용 ZIP에는 이 17개 SVG만 포함되어 있습니다.

PNG는 미리보기용이고, SVG는 Figma 임포트용입니다.
SVG 임포트는 Figma 네이티브 컴포넌트·오토레이아웃·프로토타입 연결을 복원하는 방식은 아닙니다.
텍스트를 다시 편집할 때 사용할 글꼴은 `fonts`에 포함된 IBM Plex Sans KR입니다.

기존 Figma 파일: https://www.figma.com/design/2oOCrkc9mpVE7aQcoOUhlM

이 파일에는 MCP로 만든 메인 화면과 다른 화면의 기본 프레임이 있습니다.
Starter 플랜의 MCP 호출 한도에 도달하여 전체 화면을 자동으로 추가하지 못했습니다.
전체 8개 페이지의 완성본은 이 폴더의 SVG와 로컬 미리보기에 있습니다.

## 미리보기

`index.html`을 열면 서버 설치 없이 전체 화면을 볼 수 있습니다.

- 상단 선택기로 8개 페이지를 이동합니다.
- 기기 선택기로 데스크톱 1440px와 모바일 390px 화면을 전환합니다. 페이지와 선택 상태는 유지됩니다.
- 메인·기록·도서 상세에서 리스트와 그리드를 전환합니다.
- 기록 정렬 버튼은 최신순 → 인기순 → 댓글순으로 전환합니다.
- 도서 목록에서 ‘기록이 달린 도서만 보기’ 스위치를 켜면 8권 중 6권이 남습니다.
- 도서 → 도서 상세 → 독서 기록 상세로 이동할 수 있습니다.
- 상세의 답글 버튼은 대댓글 입력 상태를 표시합니다.
- 로그인·회원가입의 오류 메시지 상태를 별도로 확인할 수 있습니다.
- ‘기록 남기기’를 누르면 작성 화면으로 이동합니다. 미리보기에서는 로그인된 상황을 가정합니다.
- 도서 상세에서 작성으로 이동하면 해당 책이 선택되어 있고, 메인에서 이동하면 도서를 검색하는 상태로 시작합니다.
- 작성 화면에서 도서 검색 → 선택 → 책 변경, ‘책 전체’ 스위치에 따른 쪽수 입력 비활성화·활성화, 필수 입력 오류를 확인할 수 있습니다.
- 모바일의 이달의 추천은 한 번에 한 편씩 표시하며 이전·다음으로 3편을 모두 볼 수 있습니다.

검색, 인증, 좋아요, 공유와 글 작성은 연결 위치를 설명하는 시안입니다. API 요청이나 실제 데이터 변경은 하지 않습니다.

## 모바일 배치

8개 페이지와 모든 대체 상태를 모바일에서도 작성했습니다. SVG는 각각 고정 크기의 와이어프레임이며 실제 앱의 반응형 CSS를 구현한 결과물은 아닙니다.

| 영역 | 모바일 배치 |
| --- | --- |
| 공통 탐색 | 로고·작성·로그인, 그 아래 독서 기록·도서 메뉴 |
| 메인 | 서비스 안내 축약 → 작은 작성 배너 → 정렬·뷰 전환 → 한 열 기록 목록 |
| 독서 기록 | 검색창 세로 배치 → 추천 1편과 이전·다음 → 2줄 분류 → 한 열 목록 |
| 독서 기록 상세 | 연결 도서를 본문 위로 이동 → 본문 → 댓글·한 단계 대댓글 |
| 도서 목록 | 검색 → 가까이 붙인 문구·필터 스위치 → 권수·정렬 → 한 줄에 한 권, 표지 옆 제목·저자·기록 수 |
| 도서 상세 | 간결한 도서 정보 → 작성 버튼 → 해당 책의 기록 한 열 |
| 로그인·회원가입 | 화면 폭에 맞는 한 열 폼, 필드별 오류 메시지 |
| 기록 남기기 | 도서 검색·선택 → 카테고리 → 2줄 편집 도구 → 본문 → 쪽수 → 작성 안내 → 등록 |

좌우 여백은 16px이며, 버튼과 스위치는 최소 44px 높이의 터치 영역으로 구성했습니다.
모바일 표지는 2:3 비율을 유지합니다. 연결 도서는 80×120px, 기록 목록은 72×108px, 도서 목록은 88×132px입니다. 도서 목록은 한 열이며 표지 옆에 도서 정보를 배치합니다. 표지 안 글자와 여백은 크기에 맞춰 조절하고 긴 제목은 최대 3줄로 제한합니다.
‘책 전체’를 켜도 쪽수 입력창을 숨기지 않고 회색 비활성 상태로 유지합니다.
모바일 작성 폼에는 고정 하단 막대를 겹치지 않게 배치해 키보드와의 충돌을 피하는 구성을 제안합니다.
320·375·390·414px 너비에서도 컨테이너 경계를 검사했습니다. 태블릿 전용 시안은 포함하지 않았습니다.

## 기존 코드와의 연결

현재의 `summary`를 화면에서는 ‘독서 기록’으로 표현했습니다.

- 메인은 `/`, 기록 상세는 `/summary/detail/[id]`, 로그인·회원가입은 기존 경로를 그대로 연결할 수 있습니다.
- 독서 기록 전체 목록, 도서 목록, 도서 상세는 새 화면 제안입니다. 실제 경로는 구현할 때 확정합니다.
- 이달의 추천은 선정 방식과 조회 API가 추가로 필요합니다.
- 도서별 전체 기록 수와 ‘기록이 달린 도서만 보기’는 도서 단위 목록 조회가 필요합니다.
- 시안의 기록 제목은 독서 기록의 첫 문장·소제목을 보여주는 형태입니다. 독립 제목 필드를 추가할지는 구현 전에 결정합니다.
- 비로그인 사용자의 ‘기록 남기기’는 로그인 후 원래 선택한 도서의 작성 화면으로 돌아오는 흐름입니다.
- 작성 화면은 기존 `/summary/create`의 도서 선택·카테고리·리치 텍스트 본문·선택 쪽수 기능에 맞췄습니다. 별도 제목이나 임시 저장 기능은 추가하지 않았습니다.
- 내 기록일 때만 더보기 메뉴에 수정·삭제를 노출합니다.
- 대댓글은 1단계 들여쓰기로 표현했습니다. 댓글 작성 상태와 비로그인 상태를 구분합니다.

## 파일

- `screens/`: 데스크톱 17개 + 같은 화면·상태의 모바일 17개, 총 34개 SVG
- `previews/`: 같은 화면의 PNG
- `overview.png`: 기본 8화면을 함께 보는 전체 개요
- `mobile-overview.png`: 모바일 기본 8화면의 전체 개요
- `screens.json`: 파일명, 화면 이름, 크기, 상태 목록
- `wireframes.js`: 화면 생성 원본과 SVG 렌더러

SVG 렌더링 결과를 직접 확인했고 페이지·상태 조합의 컨테이너 경계와 작성 화면의 연결 동작도 검사했습니다.
브라우저 자동화와 실제 API 연동은 검증 범위에 포함하지 않았습니다.
