# API·렌더링 성능 개선 · 2026-10-25

## 변경 내용

- 기록 상세·도서 상세는 전체 카탈로그 대신 해당 책 제목으로 기록을 조회하고 ISBN으로 다른 판본을 제외합니다. 페이지별 `total`이 카테고리별 집계일 수 있어 실제 응답 길이로 다음 페이지를 판단하고 중복 ID를 제외합니다.
- 기록 상세에서 얻은 도서 정보와 도서별 기록을 캐시하여 도서 상세·작성 화면에서 재사용합니다.
- HTTP 인스턴스를 재사용하면서 토큰은 매 요청 시 읽습니다. 조회 취소를 Axios `AbortSignal`에 연결하고 요청 제한 시간을 15초로 설정했습니다.
- 기본 조회 캐시는 30초, 검색은 5분, 도서 정보는 30분, 카테고리는 10분입니다. 사용하지 않는 캐시는 5분 뒤 정리합니다. 4xx 응답은 재시도하지 않고 그 외 실패는 한 번 재시도합니다.
- 최근 도서는 비로그인 상태에서 요청하지 않으며 사용자 ID별로 캐시합니다. 로그인·로그아웃 시 공개 목록·전체 카탈로그를 다시 요청하지 않습니다.
- 좋아요·댓글 변경은 해당 항목을 갱신하고 관련 목록은 다음 진입 시 갱신하도록 표시합니다.
- 댓글·대댓글 그룹화는 중첩 검색 대신 Map을 사용해 한 번 순회합니다.
- 에디터 입력은 ref에 보관하고 편집기 상태만 구독하여 전체 작성 폼의 반복 렌더링을 줄였습니다. 카드와 도서 정렬 결과도 재사용합니다.
- Google 로그인 SDK는 로그인 화면에서만 로드합니다.
- 터치·포인터 입력 후에는 조작 요소의 포커스 테두리를 숨기고 키보드 이동에서는 표시합니다. 모바일 탭 하이라이트도 제거했습니다.

## 검증 결과

API 수치는 실제 서버 벤치마크가 아닌 로컬 테스트 응답 기준입니다. 전체 기록 1,000건, 8개 도서, 대상 도서 기록 125건으로 확인했습니다.

| 항목                         | 개선 전                  | 개선 후                      |
| ---------------------------- | ------------------------ | ---------------------------- |
| 기록 상세의 도서별 집계 조회 | 전체 기록 10회 / 1,000건 | 제목 검색 2회 / 125건        |
| 기록 상세 → 도서 상세 이동   | 카탈로그 의존            | 추가 API 0회                 |
| 같은 도서 검색 반복          | 매번 POST                | 추가 API 0회                 |
| 비로그인 최근 도서 조회      | 401 요청 발생 가능       | 요청 0회                     |
| 로그아웃 시 전체 카탈로그    | 무효화 후 재조회         | 추가 요청 0회                |
| 4개 글꼴 파일의 합계         | 12,913,428바이트         | 2,915,780바이트 (77.4% 감소) |

글꼴은 fontTools의 WOFF2 압축으로 변환했고 원본 파일과 글자 매핑·가로폭 메트릭이 동일함을 확인했습니다. 글자 부분집합은 만들지 않았습니다. Gowun Batang은 실제로 사용하는 화면에서 로드하도록 선행 로드를 해제했습니다. 파일 크기 비교이며 네트워크 압축·LCP 실측치는 아닙니다.

검증 항목:

- 빈 배열을 반환하는 기존 목록 API 처리, 잘못된 합계와 중복 페이지, 요청 취소, 캐시 재사용, 인증 오류 재시도 방지, 댓글 순서·대댓글 10,000건 처리에 대한 테스트
- 모바일 탭 후 테두리 숨김과 Tab 키 포커스 표시
- 본문 입력·서식·등록, 기존 이미지·표·색상·정렬 유지, 회원가입·프로필·로그아웃
- 타입 검사·린트·프로덕션 빌드

## 남은 제약

전체 도서 목록은 백엔드에 완전한 도서별 집계 API가 없어 아직 전체 기록 조회가 필요합니다. 기존 `/book/created-rank`는 상위 3개만 반환하므로 전체 도서 목록을 대체할 수 없습니다. 서버에서 ISBN별 수·최근 기록 날짜·도서 정보를 페이지 단위로 집계하는 API를 제공하면 이 조회를 제거할 수 있습니다. 이번 변경은 현재 프런트엔드 저장소에만 적용했습니다.
